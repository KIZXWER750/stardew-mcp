# Stardew MCP 1.11.1 — 어린나무를 포함한 야생 나무·밑동 제거

1.8.0 농사·자동 물 보충·씨앗 구매·수확물 판매·일반 상자 꺼내기·F6/F7 기능을 유지하면서 판단 모델 호출부를 추가했습니다. 기본은 OpenAI Responses API의 `gpt-5.6-luna`, reasoning effort는 **medium 고정**입니다. effort 변경 UI/플래그/설정은 없습니다. 애니메이션·농사 실행 알고리즘은 이번 변경 범위가 아닙니다.

1.9.1은 OpenAI가 선택 함수 인수에 `null`을 보낼 때 발생하던 `AI_TOOL_ARGUMENTS_INVALID`를 수정합니다. 선택 필드의 `null`은 생략값으로 처리하고, 실행 전에 발견한 잘못된 인수는 게임 행동 없이 모델에 돌려보내 올바른 함수 호출로 교정합니다.

1.9.2는 피에르 상점 진입을 전용 `open_pierre_shop` 함수로 처리합니다. `SeedShop` 내부에서 `(4,19)`로 이동하고 북쪽의 판매 카운터 `(4,18)`를 한 번 상호작용하며, 실제 `ShopMenu`가 열린 경우에만 성공합니다. 피에르 NPC 대화는 구매 메뉴로 인정하지 않습니다.

1.9.3은 마을에서 피에르 잡화점으로 들어가는 경로를 고정합니다. `enter_pierre_shop`은 `Town`의 유효한 접근 칸 `(43,57)`과 `(44,57)`만 사용하고, 가까운 접근 가능 칸에서 북쪽으로 한 번 상호작용한 뒤 실제 `SeedShop` 전환을 검증합니다.

1.10.0은 AI가 하루 작업을 중단하거나 회복하고 귀가해 잠드는 데 필요한 첫 생활 함수 묶음을 추가합니다.

| 함수 | 역할 |
| --- | --- |
| `assess_daily_status` | 현재 시각·체력·에너지·위치를 읽고 보수적인 다음 행동을 제안 |
| `find_food_options` | 실제 인벤토리에서 회복 가능한 음식과 슬롯·ID·수량을 조회 |
| `find_recovery_options` | 음식·수면·목욕탕 자동화 지원 여부를 한 번에 조회 |
| `consume_food` | 관측한 음식 한 개만 일반 입력으로 먹고 수량·회복 결과 검증 |
| `find_home_route` | 현재 지역에서 `FarmHouse`까지 로드된 맵 연결을 읽기 전용으로 조회 |
| `return_home` | 관측한 출구만 따라 정상 이동하고 실제 `FarmHouse` 진입을 검증 |
| `schedule_bedtime` | 경로 홉과 안전 여유를 바탕으로 보수적인 귀가 출발 시각 계산 |
| `sleep_until_morning` | 실제 플레이어 침대의 좌우로 접근해 수면 확인창만 승인하고 다음 아침 검증 |

목욕탕 자동 회복은 탈의실 전환과 수영 상태를 별도 인게임 검증해야 하므로 이번 버전에서는 실행하지 않습니다. `find_recovery_options`가 이를 명시적으로 알려 AI가 지원되지 않는 행동을 추측하지 않게 합니다.

1.10.1은 일부 게임 빌드에서 농가 정문이 `warps`/`doors` 목록에 나타나지 않아 `FarmHouse 경로 없음`으로 차단되던 문제를 수정합니다. 맵에서 실제 간선을 찾지 못한 경우에만 이 프로젝트에서 이미 검증한 표준 농장 정문 `(64,14)`과 남쪽 접근 칸 `(64,15)`을 경로에 추가합니다. 이동·상호작용·실제 `FarmHouse` 전환 검증은 그대로 수행하므로 순간이동이나 성공 추정은 하지 않습니다.

1.10.2는 농가 건물 사각형과 실제 통행 가능한 현관 데크가 겹치는 충돌 판정을 수정합니다. Farm에서 `y=15, x=59..66` 및 `y=16, x=63..65`는 경로 계획상 통행 가능한 현관 구간으로 취급하되, 그 위의 실제 객체·지형·자원 덩어리는 계속 장애물로 검사합니다. 귀가는 다른 지역에서 `Farm`까지의 맵 경로와 `Farm -> FarmHouse` 전용 정문 진입을 분리하며, `(64,15)` 도착 후 북쪽 정문 `(64,14)`에 정상 상호작용하고 실제 내부 전환을 검증합니다.

1.10.3은 현관 영역으로 들어오는 방향까지 제한합니다. 외부에서는 남쪽의 `(63,17)`, `(64,17)`, `(65,17)`에서 각각 바로 북쪽의 `(63,16)`, `(64,16)`, `(65,16)`으로 들어가는 세 경계만 허용합니다. 동쪽·서쪽·북쪽에서 건물 벽을 가로질러 현관에 진입하거나 빠져나가는 경로는 만들지 않습니다. 현관 영역에 들어온 뒤에는 내부의 통행 가능 칸 사이를 정상적으로 이동할 수 있습니다.

1.10.4는 긴 복합 작업이 `AI_TOOL_ROUND_LIMIT`에 너무 일찍 도달하지 않도록 OpenAI 도구 실행 라운드와 상태 재관측 한도를 각각 60회에서 180회로 늘립니다. 한 목표의 실행 시간 창도 10분에서 20분으로 늘립니다. 동일 call ID 중복 방지, 동일 농사 작업 최대 3회, 농사 작업 총 24회, 불확실한 거래·행동의 자동 재시도 금지는 유지됩니다.

1.11.0은 다음 두 실행 함수를 추가합니다.

| 함수 | 역할 |
| --- | --- |
| `manage_daily_life` | 장기 단계 전후에 시간·에너지를 검사하고, 사용자에게 허용된 경우에만 가격·예비 수량·보호 ID 제한 안에서 음식을 먹거나 귀가·수면 수행 |
| `remove_wild_trees` | AI가 관측으로 고른 Farm 영역에서 일반 야생 나무를 제한된 수만큼 도끼로 베고 밑동까지 사라졌는지 검증 |

`manage_daily_life`는 백그라운드 데몬이 아닙니다. AI 시스템 규칙이 긴 작업 전과 `LOW_ENERGY`/`TIME_LIMIT` 이후에 이 체크포인트를 호출합니다. 음식 섭취와 수면은 해당 목표에서 허용되어야 하며, 보호할 아이템 ID·최대 음식 판매가·예비 수량·최대 소비 개수로 제한됩니다. 회복 결과의 `resumeRequestedWork=true`일 때만 AI가 미완료 단계를 이어갑니다.

`remove_wild_trees`는 `clear_area`와 분리되어 있습니다. 기본값은 성목과 이미 남은 일반 밑동만 대상으로 하며 어린 나무는 `include_saplings=true`가 명시되어야 합니다. 과일나무, 덤불, 작물, 건물, 기계, 배치 물체와 자원 덩어리는 대상이 될 수 없습니다. 이번 함수는 떨어진 목재·수액·씨앗을 줍지 않습니다.

1.11.1은 나무 제거의 기본 정책을 바꿉니다. 별도 보존 요청이 없으면 일반 야생 나무는 씨앗·묘목·성장 중인 나무·성목·밑동을 포함해 모든 성장 단계를 제거합니다. 어린 일반 나무를 특별히 남겨야 할 때만 `preserve_young_trees=true`를 사용합니다. `FruitTree`, 작물, 건물·상자·기계·배치 시설은 계속 대상에서 제외됩니다.

## 인증과 공급자

| 환경변수 | 용도 |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI API 키. OpenAI 모드에서만 필요. 파일·게임 입력창에 저장하지 않음 |
| `STARDEW_AI_PROVIDER` | `openai`(기본) 또는 `copilot` |
| `COPILOT_CLI_PATH` | 기존 Copilot CLI 경로. Copilot 모드에서만 사용 |

OpenAI 모드에서는 Copilot CLI 로그인/구독을 사용하지 않습니다. OpenAI API 계정에 별도 사용료가 청구됩니다. 모델 접근 권한/결제 상태가 안 되면 중단하며 다른 공급자로 자동 전환하지 않습니다. 가격 추정 대신 응답별 입력/출력 토큰 수만 로그에 남깁니다.

키는 Windows 사용자 환경변수에 설정하거나, 게임을 시작할 PowerShell 프로세스 환경에 설정하세요. 키를 명령줄 문자열·채팅·스크린샷·GitHub에 붙여 넣지 마세요. 사용자 환경변수를 바꾼 뒤에는 Steam과 SMAPI를 완전히 재시작해야 새 값이 게임 → Go 호스트 → 작업 프로세스에 상속됩니다. 환경변수는 암호화된 비밀 저장소가 아니므로 같은 사용자 권한의 프로세스에 대한 보안 경계는 아닙니다.

## 게임 없는 PC에서

```powershell
& ".\Build-Server.ps1"
.\mcp-server\stardew-mcp-ingame.exe --check-ai-config
```

Go 1.24 이상이 필요합니다. 첫 명령은 모의 API 테스트, 기존 Go 테스트, 정적 검사, Windows amd64 빌드만 수행합니다. 두 번째는 환경변수만 검사합니다. **API 연결/모델 접근/결제 검증이 아닙니다.** 게임 DLL과 API 키 없이 테스트·빌드할 수 있습니다.

## 게임 PC에서 설치

게임/SMAPI 종료 후 압축을 풀고 실행합니다. Go, .NET SDK, 설치된 Stardew Valley와 SMAPI가 필요합니다.

```powershell
& ".\Install.ps1" -GamePath "E:\SteamLibrary\steamapps\common\Stardew Valley"
```

설치기는 Go 테스트/빌드와 C# 게임 참조 빌드가 모두 성공한 뒤 기존 모드를 백업하고 교체합니다. OpenAI 모드에는 Copilot 설치가 필요하지 않습니다. `-BuildOnly`는 설치만 생략하고 게임 참조 빌드는 수행합니다. 게임 없는 빌드는 `Build-Server.ps1`을 사용하세요.

GitHub 소스 ZIP에는 exe가 없으며 설치 중 빌드합니다. 별도 배포 ZIP에는 Windows Go 서버 exe가 포함됩니다. 게임 DLL/미검증 C# 바이너리는 배포하지 않습니다.

설치 후 세이브를 열고 F6으로 목표 입력, F7로 취소합니다. 성공/실패 후 새 목표를 입력할 수 있고 결과는 기존 게임 채팅으로 전달됩니다. API 키 누락/401/429/네트워크 오류도 중단 이유로 표시합니다. 키를 바꾸면 Steam/게임을 재시작하세요.

## 구현과 안전장치

- 기존 정상 플레이 함수에 생활 관리자와 야생 나무 제거를 더한 총 **48개**의 정의와 실행기를 사용합니다. 치트 도구와 치트 매뉴얼은 OpenAI에 노출하지 않습니다.
- 함수 인수는 JSON Schema와 기존 도메인 검증을 통과해야 합니다. 알 수 없는 함수/인수는 차단합니다.
- `parallel_tool_calls=false`; 동시 함수 묶음 응답은 실행 전에 거부합니다.
- 함수 호출 ID별 결과를 재사용해 같은 ID의 재전달로 행동이 중복되지 않게 합니다. 다른 ID로 반복된 의미상 행동은 기존 농사/거래 원장과 실행 전 관측으로 보호합니다. 모든 행동에 영구 exactly-once를 보장하지는 않습니다.
- 최종 응답을 받으면 같은 목표를 자동 재시작하지 않습니다. 기존 특별 검증 토큰 루프는 유지됩니다.
- 요청 실패/불완전 응답은 자동 재전송하지 않습니다. 불확실한 행동 결과는 다시 관측해야 합니다.
- 개별 OpenAI 요청은 최대 120초, 한 목표의 도구 판단 라운드와 상태 재관측은 각각 최대 180회, 전체 목표 문맥은 최대 20분을 사용합니다. 인게임 호스트의 최종 상한 30분은 유지됩니다.
- `store=false`; 같은 작업 중 reasoning encrypted content와 함수 결과는 메모리에서만 이어 보냅니다. 키와 원본 API 오류 본문은 로그에 기록하지 않습니다. OpenAI 서비스 자체 데이터 보존 정책을 대체하는 설정은 아닙니다.
- 새 OpenAI HTTP 코드가 모델 통신을 맡고, 기존 Copilot SDK의 함수 정의/결과 타입은 호환 어댑터로 재사용합니다. Copilot SDK를 프로젝트 의존성에서 제거한 것은 아닙니다.

이번 환경에서는 새 생활 관리자와 나무 제거의 인게임 실행이 미검증입니다. 수행 범위는 VALIDATION.md에 기록했습니다. 기존 함수 계약과 게임 제약은 FUNCTIONS.md를 참고하세요.

공식 계약: [Luna 모델](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Function calling](https://developers.openai.com/api/docs/guides/function-calling).
