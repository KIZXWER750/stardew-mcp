# Stardew MCP 1.19.7 — 아침 시간 진행과 농가 출발 복구

1.19.7은 수면 뒤 입력 한 번으로 `hasMoved`만 바뀌고 시계는 오전 6시에 머물렀는데도 성공으로 판정하던 문제를 수정합니다. 실제 플레이어 위치 변화와 6시 이후 게임 시간 진행을 모두 확인해야 수면이 완료됩니다. 다음 날 농사 단계는 농가 안에서 임대하지 않고 먼저 `exit_house`로 Farm 도착을 검증합니다. Farm 전용 함수가 잘못된 위치에서 호출되어도 작업 시도로 기록하지 않으므로 이동 후 동일 작업을 안전하게 다시 호출할 수 있습니다.

1.19.6은 사용자가 매일 작업 후 귀가와 수면을 명시적으로 허용하면 그 정책을 장기 목표에 저장합니다. 오늘 계획을 완료하고 다음 단계가 미래 날짜라면 인게임 호스트가 별도의 AI 호출을 예약해 정상 이동으로 귀가하고 잠듭니다. 수면 함수가 날짜 변경, 오전 상태 안정화와 실제 시간 진행을 확인한 뒤 또 다른 AI 호출이 저장된 다음 날 계획을 이어 갑니다. 같은 날 수면 호출은 한 번만 예약해 실패 시 반복 루프를 막습니다.

1.19.5는 기존 작물의 내부 성장 단계 값이 비정상적으로 클 때 `goal_plan_build`가 수만 개의 일일 단계를 만들어 AI 도구 결과 한도를 넘던 문제를 수정합니다. 성장 대기일은 최대 28일, 저장 계획은 최대 64단계로 제한하며, 과거에 저장된 대형 계획도 자동으로 stale 처리해 재계획합니다. OpenAI 제공자에도 장기 목표·경제 계획·단계 실행 규칙을 전달하고, 도구 결과가 128KB를 넘더라도 세션을 종료하지 않고 상태 재조회 지침으로 복구합니다.

1.19.4는 다음 날 날짜가 바뀌었지만 기상 화면 전환 중이라 `CanMove=false`인 구간에서 이동 입력을 모두 소진하던 문제를 수정합니다. 화면 전환이 실제로 끝날 때까지 기다린 뒤 정상 이동 입력을 보내며, `hasMoved`와 `shouldTimePass()`가 모두 확인되어야 수면 완료로 판정합니다. 조작 가능 상태가 된 뒤에도 30초 동안 시간이 시작되지 않을 때만 오류로 처리합니다.

1.19.3은 Stardew Valley 1.6의 분리된 `StardewValley.GameData` 어셈블리에서 작물·상점 데이터 타입을 찾습니다. 계획 생성 오류 뒤 일반 행동으로 우회하지 않으며, 오늘 할 단계가 끝나고 다음 날짜·시간·성장을 기다리는 상태는 `GOAL WAITING` 체크포인트로 남겨 인게임 호스트가 조건 충족 시 같은 목표를 자동 재개합니다.

1.19.2는 인벤토리에 판매할 작물이 없을 때 농장에 이미 심어진 살아 있는 작물을 먼저 수익 후보로 계산합니다. 기존 작물의 위치·성숙까지 남은 날짜·예상 판매액을 관측하고, 해당 구역의 물주기·수확·판매만 계획합니다. 이 경로는 `tend_existing_crops` 권한으로 분리되어 씨앗 구매, 새 경작지 준비와 파종을 허용하지 않습니다.

1.19.1은 판매 가능한 수확물이 없을 때 일반 차단 메시지로 끝내지 않고 전용 질문창에서 수확물 준비·추가 행동 허용·일시정지·취소를 선택하게 합니다. 피에르 영업 전이면 오전 9시를 실행 가능 시각으로 저장하고 게임 시간이 된 뒤 자동 재개하며, 수요일·축제·영업 종료는 다음 날 오전 9시부터 다시 확인합니다.

1.19.0은 3차에서 저장한 전략을 단계별 실행권으로 연결합니다. AI는 `start_goal_plan_execution`으로 현재 계획을 시작하고, 한 번에 한 단계만 임대받아 기존의 정상 구매·농사·판매 함수를 실행합니다. 각 단계는 돈·인벤토리·경작지·작물·물주기 상태를 다시 검사한 뒤에만 완료됩니다. 실행 전 상태가 바뀌었다면 계획을 `stale`로 만들고 재계획합니다.

농사 전략은 `find_plot_candidates`가 실제로 반환한 영역만 계획에 고정하며 이후 경작·파종·물주기·수확에서 같은 좌표를 사용합니다. 다음 날 단계는 `waiting`으로 저장되고, 날짜가 되면 인게임 호스트가 자동으로 같은 목표를 이어 갑니다. F7은 실행 중인 장기 목표와 계획을 함께 일시정지합니다. 한 재배·판매 주기가 끝나도 돈 목표가 남으면 현재 상태로 재계획해 다음 주기를 계속할 수 있습니다.

계획에 필요한 행동 권한이 빠졌다면 임의로 진행하지 않습니다. `build_goal_plan`이 질문 문구와 선택지를 만들고 전용 인게임 질문창으로 답을 받은 뒤, 답변이 실제로 허용한 행동만 목표에 추가할 수 있습니다. 예비금·마감일·최종 작업 시각·보호 아이템과 `fastest`, `highest_profit`, `low_risk`, `low_effort`, `balanced` 선호도도 계속 적용됩니다.

1.17.0은 기능 지원표, 현재 경제 상태 관측, 설치된 게임 데이터 기반 작물 수익 계산, 활성 돈 목표에 맞춘 수익 기회 후보를 추가합니다. 분석 함수는 현재 돈·에너지·인벤토리 판매가·농장 작물·목표 제약을 읽고, 현재 계절의 성장 기간·재수확 주기·보유 씨앗·피에르 데이터 가격·실제 판매가로 비용과 예상 수익을 계산합니다. 결과는 읽기 전용 후보이며 전략을 자동 선택하거나 구매·농사·판매를 시작하지 않습니다.

농사 함수 `restore_tilled_soil`도 추가했습니다. 명시한 농장 영역에서 작물과 시설물이 없는 기존 경작지만 골라 곡괭이의 정상 입력·애니메이션으로 치고, 실제 `HoeDirt`가 사라져 일반 땅이 됐는지 칸마다 검증합니다.

1.9.2는 피에르 상점 진입을 전용 `open_pierre_shop` 함수로 처리합니다. `SeedShop` 내부에서 `(4,19)`로 이동하고 북쪽의 판매 카운터 `(4,18)`를 한 번 상호작용하며, 실제 `ShopMenu`가 열린 경우에만 성공합니다. 피에르 NPC 대화는 구매 메뉴로 인정하지 않습니다.

1.10.3은 현관 영역으로 들어오는 방향까지 제한합니다. 외부에서는 남쪽의 `(63,17)`, `(64,17)`, `(65,17)`에서 각각 바로 북쪽의 `(63,16)`, `(64,16)`, `(65,16)`으로 들어가는 세 경계만 허용합니다. 동쪽·서쪽·북쪽에서 건물 벽을 가로질러 현관에 진입하거나 빠져나가는 경로는 만들지 않습니다. 현관 영역에 들어온 뒤에는 내부의 통행 가능 칸 사이를 정상적으로 이동할 수 있습니다.

1.10.4는 긴 복합 작업이 `AI_TOOL_ROUND_LIMIT`에 너무 일찍 도달하지 않도록 OpenAI 도구 실행 라운드와 상태 재관측 한도를 각각 60회에서 180회로 늘립니다. 한 목표의 실행 시간 창도 10분에서 20분으로 늘립니다. 동일 call ID 중복 방지, 동일 농사 작업 최대 3회, 농사 작업 총 24회, 불확실한 거래·행동의 자동 재시도 금지는 유지됩니다.

1.11.0은 다음 두 실행 함수를 추가합니다.

| 함수 | 역할 |
| --- | --- |
| `manage_daily_life` | 장기 단계 전후에 시간·에너지를 검사하고, 사용자에게 허용된 경우에만 가격·예비 수량·보호 ID 제한 안에서 음식을 먹거나 귀가·수면 수행 |

`manage_daily_life`는 백그라운드 데몬이 아닙니다. AI 시스템 규칙이 긴 작업 전과 `LOW_ENERGY`/`TIME_LIMIT` 이후에 이 체크포인트를 호출합니다. 음식 섭취와 수면은 해당 목표에서 허용되어야 하며, 보호할 아이템 ID·최대 음식 판매가·예비 수량·최대 소비 개수로 제한됩니다. 회복 결과의 `resumeRequestedWork=true`일 때만 AI가 미완료 단계를 이어갑니다.

1.11.0 당시의 `remove_wild_trees`는 `clear_area`와 분리해 성목과 밑동만 제거하고 드롭은 수집하지 않았습니다. 아래 1.11.1과 1.11.2에서 각각 어린나무 기본 제거와 드롭 회수 기능으로 이 동작을 대체합니다.

1.11.1은 나무 제거의 기본 정책을 바꿉니다. 별도 보존 요청이 없으면 일반 야생 나무는 씨앗·묘목·성장 중인 나무·성목·밑동을 포함해 모든 성장 단계를 제거합니다. 어린 일반 나무를 특별히 남겨야 할 때만 `preserve_young_trees=true`를 사용합니다. `FruitTree`, 작물, 건물·상자·기계·배치 시설은 계속 대상에서 제외됩니다.

1.11.2는 기존 주변 직렬화가 `location.Objects`만 검사해 나무에서 생성되는 실제 `location.debris`를 누락하던 문제를 수정합니다. 느슨한 드롭의 좌표·아이템 ID·수량·청크 수를 관측에 포함하고, `remove_wild_trees`가 나무와 밑동 제거 후 주변 드롭이 안정될 때까지 기다린 뒤 정상 이동으로 회수합니다. 기본 도끼의 단계별 안전 한도는 성목 10회, 밑동 5회, 어린나무 4회이며 실제 지형 변화가 더 일찍 확인되면 즉시 다음 단계로 넘어갑니다.

1.11.3은 `max_trees` 대상이 단순 거리순으로 정해져 가까운 어린나무만 선택되던 문제를 수정합니다. 같은 영역에서는 성목을 먼저 선택하고, 그다음 기존 밑동, 마지막으로 어린나무를 선택합니다. 같은 성장 분류 안에서만 플레이어와의 거리를 사용합니다.

1.12.0은 농장 이동 전용 `move_with_clearing`을 추가합니다. 일반 경로와 제거 가능한 자연 장애물을 통과하는 경로를 비용으로 비교해, 짧은 우회가 있으면 그대로 걷고 지나치게 긴 우회나 단절 구간은 필요한 장애물만 제거합니다. 잔디·잡초·잔가지·작은 돌·어린 일반 나무·일반 나무 밑동만 허용하며 성목, 과일나무, 작물, 경작지, 건물, 상자, 기계, 가구, 울타리, 자원 덩어리와 기타 배치 시설은 경로로 사용할 수 없습니다. 각 장애물 제거와 최종 목적지 도착을 실제 상태로 검증합니다.

드롭으로 가는 경로가 막히면 지원되는 일반 야생 나무·잔디·잡초·작은 돌·잔가지만 제한된 수 안에서 제거하고 다시 접근합니다. 과일나무, 작물, 경작지, 건물, 상자, 기계, 가구와 배치 시설은 제거하지 않습니다. 인벤토리가 가득 찼거나 보호 대상 때문에 접근할 수 없으면 성공을 추정하지 않고 부분 상태로 중단합니다.

게임/SMAPI 종료 후 압축을 풀고 실행합니다. Go, .NET SDK, 설치된 Stardew Valley와 SMAPI가 필요합니다.

```powershell
& ".\Install.ps1" -GamePath "E:\SteamLibrary\steamapps\common\Stardew Valley"
```

설치기는 Go 테스트/빌드와 C# 게임 참조 빌드가 모두 성공한 뒤 기존 모드를 백업하고 교체합니다. OpenAI 모드에는 Copilot 설치가 필요하지 않습니다. `-BuildOnly`는 설치만 생략하고 게임 참조 빌드는 수행합니다. 게임 없는 빌드는 `Build-Server.ps1`을 사용하세요.

GitHub 소스 ZIP에는 exe가 없으며 설치 중 빌드합니다. 별도 배포 ZIP에는 Windows Go 서버 exe가 포함됩니다. 게임 DLL/미검증 C# 바이너리는 배포하지 않습니다.

설치 후 세이브를 열고 F6으로 목표 입력, F7로 취소합니다. 성공/실패 후 새 목표를 입력할 수 있고 결과는 기존 게임 채팅으로 전달됩니다. API 키 누락/401/429/네트워크 오류도 중단 이유로 표시합니다. 키를 바꾸면 Steam/게임을 재시작하세요.

## 구현과 안전장치

- 기존 정상 플레이 함수에 생활 관리자, 야생 나무 제거와 장애물 정리 이동을 더한 총 **49개**의 정의와 실행기를 사용합니다. 치트 도구와 치트 매뉴얼은 OpenAI에 노출하지 않습니다.
- 함수 인수는 JSON Schema와 기존 도메인 검증을 통과해야 합니다. 알 수 없는 함수/인수는 차단합니다.
- `parallel_tool_calls=false`; 동시 함수 묶음 응답은 실행 전에 거부합니다.
- 함수 호출 ID별 결과를 재사용해 같은 ID의 재전달로 행동이 중복되지 않게 합니다. 다른 ID로 반복된 의미상 행동은 기존 농사/거래 원장과 실행 전 관측으로 보호합니다. 모든 행동에 영구 exactly-once를 보장하지는 않습니다.
- 최종 응답을 받으면 같은 목표를 자동 재시작하지 않습니다. 기존 특별 검증 토큰 루프는 유지됩니다.
- 요청 실패/불완전 응답은 자동 재전송하지 않습니다. 불확실한 행동 결과는 다시 관측해야 합니다.
- 개별 OpenAI 요청은 최대 120초, 한 목표의 도구 판단 라운드와 상태 재관측은 각각 최대 180회, 전체 목표 문맥은 최대 20분을 사용합니다. 인게임 호스트의 최종 상한 30분은 유지됩니다.
- `store=false`; 같은 작업 중 reasoning encrypted content와 함수 결과는 메모리에서만 이어 보냅니다. 키와 원본 API 오류 본문은 로그에 기록하지 않습니다. OpenAI 서비스 자체 데이터 보존 정책을 대체하는 설정은 아닙니다.
- 새 OpenAI HTTP 코드가 모델 통신을 맡고, 기존 Copilot SDK의 함수 정의/결과 타입은 호환 어댑터로 재사용합니다. Copilot SDK를 프로젝트 의존성에서 제거한 것은 아닙니다.
